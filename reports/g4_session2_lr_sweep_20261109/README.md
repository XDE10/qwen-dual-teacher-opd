## 分析

**学生熵下降主要是 rollout 换了位置，不是学生相对教师变尖。**
- 在学生自己的 rollout 上，教师的熵和学生的熵一起下降：math 教师熵从 1.26 降到 0.49–0.80。
- 两者之比在 math 上一直在 0.2–0.25 附近（逐步波动在 0.13–0.44 之间）；code 从 1.07 降到 0.86–0.88。
- 如果学生只是整体降温，教师在同一批文本上的熵不会减半。实际情况是：学生转向了两个模型都很有把握的写法。

**数学教师最初的高熵落在格式 token 上。** 探针给出 KL 最多的 token：
- 空格（教师熵 1.39，学生 0.14）、LaTeX 的 ` \` 和 ` \(`、双空格（教师熵 1.95，学生 0.03），以及回答末尾的 `<|im_end|>`（平均 KL 1.84，教师熵 3.42，学生 0.09）。
- 数字 token 的 KL 只有 0.15–0.20。前 40 个 token 只占 KL 的 42%，分歧分散在整篇文本上。

**OPD 先学到的是格式。**
- 保守判分器与 Math-Verify 的准确率差距，从第 1 步的 0.23 缩到第 21–30 步的约 0.06，三个学习率都是如此。
- 回答最后一成位置的 KL 从 0.71 降到 0.25–0.27（1e-5 为 0.40）。

**reverse KL 的选峰性从一开始就存在。** math 上学生比教师尖约 4–5 倍，这个比例训练前就是如此，30 步内没有明显变化；code 上学生从比教师略宽（1.07）变成略尖（0.86–0.88）。

**学习率只改变走完同一过程的速度。** 1e-4 大约快 3 倍：
- math–code 梯度余弦的峰值：1e-4 在第 5 步（0.15），3e-5 在第 10 步（0.19），1e-5 到第 30 步仍在上升；前两组之后都回到约 0。这说明早期两域共享一个方向（格式），之后各自更新，没有出现梯度冲突。
- 1e-4 的 code 熵在第 11 步降到最低（0.23），之后回升到 0.35，接近教师在同一批文本上的 0.40；3e-5 到第 30 步仍在下降。
- math 熵在 1e-4 下从第 11 步起停在 0.09–0.10。

**影响。**
- 每 token 熵约 0.1 nats，意味着采样多样性下降：pass@k、多数投票的余量变小；如果以后再接 RL，探索也会不足。我们的主指标 greedy pass@1 不直接受影响。
- on-policy 状态变窄，再往后训练的收益会递减。
- math 回答变长 10–15%。在 1024 token 的训练上限下，截断率从 3% 升到 8%，被截断的 rollout 几乎全错（准确率 0–4%，正常结束的为 69–75%）。评测上限是 2048 token。
- 在线准确率的上升混有两个因素：格式向教师靠拢，以及 T=1 采样随熵下降而接近 greedy。是否真有能力提升，要看 greedy dev 评测与 D0 的比较。

## 稳定性关卡：v1 的问题与 v2

**v1 的问题。** v1（各 run 里的 `summary.json`）比较首尾两个 10 步窗口，并把学生熵的绝对变化当作硬条件。结果：
- 三组都因 math 学生熵失败，3e-5 还因 code 学生熵失败。
- 学习率大时，第一个窗口里已经包含了大部分变化，所以比值偏小。例如 1e-4 的 code 熵，按窗口算是 0.80（通过），相对第 1 步实际是 0.59。

**v2 的改法（`scripts/summarize_run_v3.py`）：**
- 以该域第一步为基线。
- 用"学生熵 ÷ 教师熵"的相对变化（0.7–1.5 倍）检查选峰性，学生熵的绝对变化只作提示。
- 其余条件不变。

**v2 结果。** 三组都通过。
- 3e-5：提示 math 熵降到 0.32 倍、code 降到 0.48 倍；math 的相对比值为 0.74，最接近 0.7 的下限，续跑时要盯住。
- 1e-4：提示 math 熵降到 0.31 倍。
- `gate_v1_first_window` 字段保留了 v1 的结果。

## 决定

- **主实验：** `d4_dual`（3e-5）从 checkpoint-30 续跑到 80 步。
  - 到第 21–30 步，3e-5 与 1e-4 的配对在线准确率已无显著差异。
  - D1/D2/D3/blocked/warm start 的配置都用 3e-5，不需要另建一套。
  - 已经跑完的 30 步可以直接复用。
  - 1e-4 和 1e-5 的 checkpoint-30 保留，作为学习率敏感性的记录。
- **先做 dev 评测再看：** 在投入完整矩阵之前，对三个 checkpoint-30 做 greedy dev 评测（math_dev + code_dev），与 D0 比较。如果 1e-4@30 在 math_dev 上领先 3e-5@30 超过 5 个点（256 题中约 13 题），且 code_dev 不低，就改用 1e-4 并补建对应配置；否则保持 3e-5。只用 dev 做这类选择，不看测试集。
- **近端教师：** `proximal_teacher_alpha` 不用于主实验，`configs/project2_opd_v3_d4_prox07.json`（α=0.7）作为消融备用。触发条件见 `docs/handover/kiro_ide_onboarding.md`。
