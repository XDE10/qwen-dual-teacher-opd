## 教师适配度探针（未训练学生的 64+64 条 rollout）

逐 token 精确反向 KL（nats/token），括号里是教师在学生回答上的平均熵。学生自己的熵：数学 0.317，代码 0.588。

| 教师 | 数学 | 代码 |
| --- | --- | --- |
| Qwen2.5-Math-7B-Instruct（数学专家） | **0.369**（1.263） | 0.731（2.229） |
| Qwen2.5-Coder-7B-Instruct（代码专家） | 0.118（0.290） | **0.223**（0.551） |
| Qwen2.5-7B-Instruct（通用） | 0.154（0.255） | 0.297（0.471） |

加粗的是 D4 实际路由的两个格子。MOPD（§4.4.2）的参照点：同源教师约 0.04，导致失稳的外部强教师约 0.19。

- **数学专家离学生最远。** 它在数学上的 KL（0.369）约为 MOPD 失稳案例的 2 倍，比代码教师（0.118）和通用教师（0.154）在数学上都高。
- **数学教师在学生回答上的分布更散。** 它的熵是 1.26，学生是 0.32，另外两位教师在数学上是 0.25–0.29。学生采样的 token 在它那里的平均对数概率是 −0.68，另外两位是 −0.43 / −0.47。它给出 <1e-2 概率的学生 token 占 4.6%，另外两位是 2.4% / 2.9%。
- **数学教师的 KL 在回答末尾升高。** 按回答相对位置分 10 段：前 7 段 0.25–0.34，最后 3 段 0.41、0.50、0.71。另外两位教师在数学上各段平稳（0.10–0.22）。分歧具体落在哪些 token 上，第二次上卡的逐 token 输出会给出。
- **代码教师在代码上 0.223**，与 MOPD 的失稳案例相当，两者熵接近（0.55 / 0.59）。
- **预计风险方向与 MOPD 不同。** MOPD 的 PG 形式表现为熵坍缩（0.30 → 0.21）。我们用精确 KL，优化目标就是教师分布，所以数学这一侧更可能出现学生熵**上升**、向教师的 1.26 靠拢。关卡对熵的两个方向都设了阈值。

## 据此做的改动（提交在 `feat/opd-v3-mopd-data-v5`）

- 显存余量大：所有 opd-v3 实验配置（smoke 除外）改为每步 64 math + 64 code，训练 micro-batch 改为 32768 token。HF rollout 的耗时主要由解码步数决定，预计批量加倍对每步耗时影响不大（待第二次上卡实测）。80 步约等于两遍训练集。
- 训练时用 Math-Verify 和保守判分器给学生自己的数学 rollout 打分（只作遥测，不进损失）。`summarize_run_v3` 加了稳定性关卡：KL 下降；熵在 0.7–1.5 倍内；回答长度在 0.7–1.3 倍内；EOS 率下降不超过 0.10；数学 rollout 准确率下降不超过 0.08；梯度范数尖峰不超过 1 次。
- 探针输出每个格子里 KL 最多的 token，`--dump-tokens K` 输出前 K 条 rollout 的逐 token 数值，用来查明数学教师的分歧集中在哪里。
- 训练入口加了 `--stop-at-step` 和 `--resume-from latest`：先跑 30 步看关卡，通过后从同一个 checkpoint 继续到 80 步。
- 学习率探测用的两个配置：`d4_dual_lr1e-5`、`d4_dual_lr1e-4`，和 `d4_dual`（3e-5）只差学习率。
- 第二次上卡的步骤见 `docs/colab_cli_wsl2.md`。
