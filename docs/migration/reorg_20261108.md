## 1. 重排目标与原则

1. **只保留项目二主线**：项目二 = 数学与代码双教师 token-level OPD。项目一（数学 7B 后训练）与项目三（多模态几何推理）的代码、测试、配置、文档不再混装。
2. **删除不等于失去证据**：被冻结发布清单用 sha256 锚定的文件，即使原路径删除，也必须保持字节可校验，因此原样镜像到 `provenance/`。
3. **不可变身份不刷新**：旧 manifest、批准字段、既有 SHA、`src/losses/reference.py` 等不因重排而修改。
4. **可追查**：删除/移动都留下台账（`inventory_before_reorg.json`、`path_mapping.json`、`deletion_ledger.json`、`provenance/`），任何"这个文件去哪了"都能回答。

## 4. provenance 机制

为什么需要它：`data/portable_release/manifest.json` 等**冻结清单**用 sha256 记录了 `inputs` 中的证据文件（数据来源 manifest、审核记录、冻结协议等）。重排删除了这些文件的旧路径，但清单不允许改写，否则等于篡改发布身份。

做法：

1. 把这 57 个文件按**原相对路径**镜像到 `provenance/`，逐字节复制，`sha256` 与清单一致。
2. `docs/migration/path_mapping.json` 记录每个条目的 `original`、`new_location`、`status`、`expected_sha256`、`actual_sha256`、`bytes`、`sha_matches`。
3. 校验器先按原路径查找，缺失时回退到 `provenance/`，再比对期望 sha256。
4. `provenance/` 只作证据存档，**不参与训练/评测的运行时读取**。

`path_mapping.json` 共 70 条，状态分布：`mirrored` 57、`kept` 10（仍在原位、无需镜像）、`moved` 2（随文档迁移位置）、`missing_before_reorg` 1。

### 已知缺口（重排前即存在）

- `data/project3_audit/geometry3k_intergps_links.jsonl`：`data/portable_release/manifest.json` 的 `inputs` 中有它的 sha256 记录，但该文件在**重排前就已不在仓库中**。映射表标记为 `missing_before_reorg`，**不是本次删除造成**，也没有伪造替代文件。引用该证据的校验只能把它当已知缺口报告。

## 6. 如何恢复或追查已删文件

1. **查去向**：先看 `docs/migration/path_mapping.json`（是否只是移动/镜像），再查 `provenance/`（是否被冻结清单锚定）。
2. **查删除清单**：`docs/migration/deletion_ledger.json` 给出本次删除的文件路径；`docs/migration/inventory_before_reorg.json` 给出重排前每个文件的 `[bytes, sha256]`。
3. **恢复**：从仓库外的现存副本（个人备份、其他项目目录、云盘等）取回候选文件，计算 sha256 与快照核对；**只有 sha256 一致才可认为恢复的是原文件**。
4. **不可恢复时**：明确记录"该文件已删除且无现存副本"，不要用相似文件冒充。原始来源 `modern_genai` 仓库已清理，不能从它恢复。
5. 恢复任何文件前先确认它是否属于当前批准范围；把历史文件放回 `data/`/`reports/` 不会自动获得训练/评测批准。
